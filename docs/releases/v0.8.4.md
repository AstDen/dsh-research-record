# 0.8.4 — the published package carries every module it imports

0.8.3 shipped without `services.js`: the file is imported by `notebook`,
`guard`, `provenance`, `scaffold`, `stack` and `telemetry`, but it was missing
from `package.json` `files`. A package installed from the repository (rather
than run from a clone or a workspace symlink) failed at import:

```
Cannot find module '…/dsh-research-record/services.js'
```

The symlink hid it — a symlink to the checkout has every file, the tarball does
not. `0.8.4` fixes the manifest and adds the test that would have caught it.

## Install

```
git clone https://github.com/AstDen/dsh-research-record.git
dsh plugin --profile web add /path/to/dsh-research-record
```

or, pinned to a commit:

```
dsh plugin --profile web add 'github:AstDen/dsh-research-record#<sha>'
```

`dsh` >= 0.2.0, Node >= 22, Python 3 with `matplotlib` and `numpy` for the
figure helpers. No runtime dependencies.

## What changes for you

If you installed 0.8.3 from git, DSH could not load the bundle at all. Reinstall
with this release (or the commit it tags) and restart the host process.

`npm pack --dry-run` now reports 51 files including all sixteen runtime modules,
and `smoke-regress.mjs` gained `M18`: every relative import `./x.js` in a
published module must be covered by the manifest's `files`. On the 0.8.3
manifest it fails with `notebook.js -> services.js`; on 0.8.4 it passes.

## Upgrading

Nothing to change in a project — the dictionaries and policy format are the
same. Restart the host DSH process after reinstalling so the new bundle is the
one loaded.
